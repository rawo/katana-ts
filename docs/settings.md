# KATANA Gen 3 settings reference

Every setting BOSS TONE STUDIO for KATANA Gen 3 (1.1.0 build 26, macOS) knows for the amp, joined from three data files in its bundled web UI (source S1 in `protocol.md`):

- `js/config/address_map.js`: address, size, range, default and internal name of every setting;
- `export/item.json`: which UI control edits which setting (`pid` = area, block, byte offset);
- `export/layout.div`: each control's page, label, value list and display format.

Generated by `scripts/bts_settings.py` from the user's own installation; only data tables are read, no logic is copied. **Nothing here is verified on the amp** unless the App column names one of the app's checked parameters (`katana-proto/src/params.rs`); `protocol.md` stays the record of verified facts.

Reading the tables:

- Addresses are 4 base-128 digits; a block's settings follow its base address at their byte offset.
- Range and Default are displayed values. The raw byte is displayed + `ofs`; when they differ, the raw range is shown too (e.g. `-50–50 (raw 0–100)`).
- Bytes: `1` = one 7-bit byte; `(nibbles)` = 4 bits per byte, high first (`protocol.md`, value encodings).
- Tone Studio control: the control's label and its page in Tone Studio's layout.
- Values: the control's value names, display format or value list. Long lists are in [Value lists](#value-lists) at the end, referenced as `L1`, `L2`, ….

Patch: 80 blocks, 802 distinct settings (771 with a Tone Studio control). The app checks 35 of them today.

## Areas

| Base | Area | What |
|---|---|---|
| `00 00 00 00` | SETUP | Current channel selector |
| `10 00 00 00` | SYSTEM | Global settings, not stored per patch |
| `20 00 00 00` | PATCH | Current patch (edit buffer); stored channels use the same layout (`protocol.md`) |
| `30 00 00 00` | TEMP | Panel knob positions while editing |
| `7F 00 00 00` | COMMAND | Editor commands |

## Patch: MOD and FX

MOD and FX share one type list and one settings layout. FX(n) holds the type; FX_DETAIL(n) holds the settings of every type at once, so switching type keeps each type's settings. Type pages appear in `layout.div` in type-value order (checked against the type list's display order and the FX_DETAIL names).

Type blocks: FX(1) `20 00 10 00`, FX(2) `20 00 12 00`, FX(3) `20 00 14 00`, FX(4) `20 00 16 00`, FX(5) `20 00 18 00`, FX(6) `20 00 1A 00`.
Settings blocks: FX_DETAIL(1) `20 00 1C 00`, FX_DETAIL(2) `20 00 1E 00`, FX_DETAIL(3) `20 00 20 00`, FX_DETAIL(4) `20 00 22 00`, FX_DETAIL(5) `20 00 24 00`, FX_DETAIL(6) `20 00 26 00`.
