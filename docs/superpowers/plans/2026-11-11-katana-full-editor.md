# Full Editor (chain and hidden settings) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Tone Studio setting for booster, MOD, FX, DELAY, DELAY 2, REVERB, SOLO, EQ 1/2, CONTOUR and the AMP's hidden settings is editable in all three colours, and the chain order can be changed by dragging blocks.

**Architecture:** `scripts/bts_settings.py --rust` turns Tone Studio's tables into a checked-in Rust table (`katana-proto/src/settings_gen.rs`). `katana-proto/src/settings.rs` expands it into `ParamDef`s (existing parameters win on equal addresses) and answers "which settings does this panel show". `katana-proto/src/chain.rs` holds the chain orders and drag moves. A CLI `check-settings` run proves every new setting on the amp before the GUI uses it. The GUI gets colour tabs, a TYPE drop-down, new panels and drag-and-drop on the chain row.

**Tech Stack:** Rust workspace (`katana-proto`, `katana-cli`, `katana-gui` on egui/eframe, `egui_kittest` tests), Python 3 generator (stdlib only).

**Spec:** `docs/superpowers/specs/2026-11-10-katana-full-editor-design.md`. Data: `docs/settings.md` (generated). Facts: `docs/protocol.md`.

## Global Constraints

- KATANA Gen 3 100 only. No other models.
- Out of scope: pedal FX, noise suppressor, send/return, `ASSIGN_*`, SYSTEM; knob assignments other than PRESET.
- Nothing is ever stored into a channel by this work (no `PATCH_WRITE`, no `store_*` calls), including the check run.
- SOLO_DELAY (`20 00 3E 00`, 14 bytes, `device::WRITE_PROTECTED`) is shown read-only, never written.
- Existing parameter names stay (`delay1-time`, `delay2-*` = DELAY(2) RED, `reverb1-level`, `mod1-<type>-<setting>`, …). DELAY 2 is DELAY(4..6), named `delay4`..`delay6`.
- No Tone Studio look: the app's own palette (`theme.rs`), no copied block colours or graphics. Only data is taken.
- The app never reads Tone Studio at runtime; `settings_gen.rs` is generated by a dev tool and checked in.
- egui's default fonts have no "●", "→", "▾" or emoji: use words or painted shapes. Every widget has an accessible name (kittest finds widgets by label).
- Must build and run on macOS and Linux. `cargo clippy --workspace --all-targets` adds no warnings beyond the 3 known ones.
- Work on branch `feature/full-editor` from `main` at `30a916f`.

## Review Focus

1. A patch with odd values (MOD type 31..127, CHAIN 9..127, LAYER_MODE 3+, EQ TYPE 2+, CONTOUR 4+) from an old `.syx` or a Tone Exchange set: panels show "? (n)", the chain falls back to CHAIN 2's order, nothing panics. Tests in Tasks 5, 10.
2. Live on and the amp re-applies the knob after a colour change (DT1s for delay HIGH CUT, reverb LOW CUT..EFFECT LEVEL): the panel shows the amp's new values and sends nothing back. Test in Task 6.
3. The window at `MIN_WINDOW` with HARMONIST (most settings) selected: the panel wraps and scrolls; the amp strip stays reachable. Test in Task 6.
4. A drop, a colour-tab click or a TYPE change while an amp job runs (`amp_idle()` false): ignored like every other edit, nothing sent. Test in Task 11.
5. The colour the amp plays changes (panel press with Live on) while the user looks at another colour's tab: the tab the user picked stays selected, the outline moves. Test in Task 6.

**Interfaces:**
- Produces:
  - `pub enum Format { Plain, Signed, PlusOne, Unit(&'static str), SignedDb, HalfDb, Tenths, Percent2, OffBelowZero, Names }` (Copy, Eq, Debug) in `katana-proto::params`, re-exported from the crate root.
  - `ParamDef.format: Format`.
  - `ParamDef.ofs: i32` (was `u32`).
  - `pub fn format_value(def: &ParamDef, raw: u32) -> String` in `katana-proto::params`: the shown text. Shown number `v = raw as i64 − ofs`. `Plain` → `v`; `Signed` → `+v` when `v > 0`; `PlusOne` → `v+1`; `Unit(u)` → `"{v} {u}"`; `SignedDb` → `"+v dB"`; `HalfDb` → `"+{v/2:.1} dB"`; `Tenths` → `"{v/10:.1} s"`; `Percent2` → `"{2v} %"`; `OffBelowZero` → `"OFF"` if `v < 0` else `v`; `Names` → the value name from `values`, else `"? ({raw})"`. `Plain` with `ofs > 0` behaves like `Signed` (keeps today's knobs).
  - `pub fn parse_shown(def: &ParamDef, text: &str) -> Option<u32>` in `katana-proto::params`: inverse of `format_value` for a typed number. Unit suffixes are optional; `HalfDb` accepts halves ("3.5"), `Tenths` accepts one decimal, `Names` accepts a value name (case-insensitive). The result must lie within `min..=max`.
  - Widget rule in `param_control`: `values == Some(ON_OFF)` → toggle; `values.is_some() && format != Names` → drop-down; otherwise → `Knob`, whose text is `format_value`.

**Interfaces:**
- Consumes: `Format`, `ParamDef` (Task 1).
- Produces (in `settings_gen.rs`, plain data):
  - `pub struct GenSetting { pub key: &'static str, pub label: &'static str, pub offset: u32 /* linear byte offset in block */, pub encoding: Encoding, pub min: u32, pub max: u32 /* raw */, pub ofs: i32, pub values: Option<&'static [(u32, &'static str)]>, pub format: Format, pub types: &'static [u32] /* empty = every type */ }`
  - `pub struct GenBlock { pub table: &'static str, pub inst: &'static [(&'static str, u32)] /* (instance name, linear base) */, pub settings: &'static [GenSetting] }`
  - `pub const BLOCKS: &[GenBlock]`.
- Produces (in `settings.rs`):
  - `pub(crate) static GENERATED: LazyLock<Vec<ParamDef>>` — one def per (instance, setting), named `"{inst}-{key}"`, skipping any address already covered by `PARAMS` or `modfx::GENERATED`.
  - `pub fn def_at(addr: u32) -> Option<&'static ParamDef>` — the def (existing or generated) at a linear address.
  - `pub fn setting(table: &str, inst: usize, key: &str) -> Option<&'static ParamDef>` — e.g. `setting("REVERB", 0, "layer-mode")`.
  - `pub fn gen_block(table: &str) -> &'static GenBlock` (panics on an unknown table; tables are compile-time constants).

Generator rules:
- Tables in scope and instance names: `AMP` → `amp`; `OTHER` → `other` (only `CHAIN`, `MASTER_KEY`); `SW` → `sw` (only `DELAY2_SW`); `BOOSTER` → `booster1..3`; `FX` → `mod1..3, fx1..3` (key `type`); `FX_DETAIL` → `mod1..3, fx1..3`; `DELAY` → `delay1..6`; `REVERB` → `reverb1..3`; `SOLO_COM` → `solo`; `SOLO_EQ` → `soloeq`; `SOLO_DELAY` → `solodelay`; `CONTOUR_COM` → `contour`; `CONTOUR` → `contour1..3`; `EQ_EACH` → `eq1, eq2`; `EQ_PEQ` → `peq1, peq2`; `EQ_GE10` → `geq1, geq2`.
- Only settings with at least one Tone Studio control (BOOSTER `SOLO_SW`/`SOLO_LEVEL` included only if they have one).
- `key`: the id after the table prefix, lowercased, `_` → `-` (`PRMID_PATCH_REVERB_LAYER_MODE` → `layer-mode`, `PRMID_PATCH_FX_DETAIL_CHORUS_LOW_RATE` → `chorus-low-rate`).
- `label`: the Tone Studio control label (the generator already finds it); fallback: key upper-cased with spaces.
- Raw range: `min + ofs ..= max + ofs` from `address_map.js`; `ofs` = Tone Studio `ofs`.
- `values`/`format`: select-box options → `values` (by value) with the format left `Plain` (drop-down); hidden string lists → `values` + `Format::Names` (knob); JS format expressions → the matching `Format` variant (the `js_format` table maps one to one); 0/1 check boxes → `values: ON_OFF`.
- `types`: FX_DETAIL settings → the type value whose page holds the control; DELAY settings → the delay types of their page (`DELAY_PAGES`: `delay-delay` = 0, 2, 3, 4, 5; `delay-pan` = 1; `delay-modulate` = 6; `delay-sde3000` = 7; a setting on several pages gets their union, TYPE/TIME etc. on every page → empty); REVERB → `reverb-reverb` = 0, 1, 2, 4; `reverb-spring` = 3.
- `MASTER_KEY` gets `types: &[12]` (HARMONIST) though it lives in OTHER.

- Consumes: `settings::GENERATED`, `read_patch`, `read_blocks`, `write_patch`, `set_param`, `device::is_write_protected`.
- Produces:
  - `pub struct CheckResult { pub name: &'static str, pub wrote: u32, pub read: Option<u32> }` with `fn passed(&self) -> bool { self.read == Some(self.wrote) }`.
  - `pub fn check_settings(t: &mut dyn Transport, defs: &[&'static ParamDef], timeout: Duration) -> Result<Vec<CheckResult>, ProtoError>`: reads the current patch first; for each def (write-protected ones skipped) writes a test value, `min` if the current value ≠ `min` else `max`, pacing with `device::SEND_INTERVAL`; after each block's writes reads that block back with `read_blocks` and records results; at the end `write_patch(original)` and reads the patch back, returning `ProtoError` if it differs (outside `WRITE_PROTECTED`).
  - CLI: `katana-cli check-settings [--table NAME] [--yes]` — backs up the current patch with `backup::write_backup` (`what` = `"before-check"`), prints the backup path, asks unless `--yes`, runs only the defs from `settings::GENERATED` (not the existing verified ones; `--table` narrows to one table), prints one line per failure (`name wrote N read M`) and a summary `"N of M passed"`, exit code 1 if any failed.
